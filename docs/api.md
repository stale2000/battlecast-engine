# Library API

```ts
import { Encounter } from 'battlecast-engine';
```

The package has three layers. Most callers only need the first.

1. **Encounter** (`src/api`) - the state engine: setup, lifecycle, DM edits,
   observation, serialization
2. **Engine primitives** (`src/engine`) - the pure rules functions the
   Encounter wraps: `applyDamage`, `resolveAttack`, `executeRound`,
   `moveToward`, dice
3. **Content** (`src/data`) - 317 SRD monsters, 12 hero classes, spell and
   map data

## Encounter

### Construction and setup

```ts
const enc = new Encounter({ gridSize: 20, seed: 42 });
```

- `gridSize`: 4-100 cells (1 cell = 5 ft), default 20
- `seed`: string or number. Seeded encounters are deterministic end to end.
  Omit for `Math.random` behavior.

```ts
enc.addCreature({ monster: 'Goblin Warrior', team: 'red', count: 4 });
enc.addCreature({ heroClass: 'Fighter', heroLevel: 5, team: 'blue' });
enc.addCreature({ monster: 'Ogre', team: 'blue', position: { x: 15, y: 10 } });
```

Auto-placement puts red on the left third of the grid, blue on the right,
footprint-aware. Explicit positions are validated (bounds, occupancy,
terrain) and throw `EncounterError` with a reason if invalid. Returns the
created ids: stable, guessable strings like `goblin-warrior-red-2`.

### Lifecycle

```ts
enc.phase            // 'setup' | 'active' | 'complete'
enc.start()          // rolls initiative, freezes setup; returns the order
enc.runRound()       // AI plays one full round; returns logs + events delta
enc.runToCompletion(maxRounds?)   // default 50; returns winner
```

`runRound()` returns a `RoundResult`: the round number, the `BattleLog`
entries and `AnimationEvent`s generated by that round only, plus
completion state. Events carry hp before/after snapshots, so a consumer
can replay a battle visually without re-running any math.

### DM controls

All of these route through the engine's sanctioned primitives and throw
`EncounterError` with a human-readable reason on invalid input.

```ts
enc.damage(id, amount, damageType?)   // full pipeline: resistances, temp HP, dying
enc.heal(id, amount)                  // clamped, revives the dying
enc.addCondition(id, 'prone', duration?)
enc.removeCondition(id, 'prone')
enc.moveCreature(id, { x, y })        // validated teleport
enc.removeCreature(id)
enc.setTeamTactics('red', 'kiting')
```

### Observation

```ts
import { observeEncounter } from 'battlecast-engine';
observeEncounter(enc, logLines?)  // EncounterView - compact, JSON-safe, LLM-friendly
```

Per creature: hp string, position, size, ac, speed, conditions, and a
status of `ok | bloodied | dying | dead`. Plus round, initiative order,
team tallies, winner, and recent log lines. `enc.state` is the escape
hatch to the raw mutable `BattleState` if you need everything.

### Serialization

```ts
const snapshot = enc.toJSON();                 // plain JSON, self-contained
const restored = Encounter.fromJSON(snapshot); // resumes identically
```

The snapshot includes the seeded RNG position, so a restored battle
continues exactly as the original would have.

## Engine primitives

Exported for callers who need finer control than whole AI rounds (see
`src/index.ts` for the full list):

```ts
initBattle, executeRound, runBattle, runMonteCarlo,
createCreature, createCreatureWithFixedHp,
applyDamage, applyHealing, applyCondition, checkBattleComplete,
moveToward, isPositionBlocked, getFootprintSize, creatureDistance,
rollDice, rollD20, rollAttack, rollSave, abilityModifier
```

Two invariants to respect if you drop to this layer (inherited from
BattleCast, where this engine runs in production):

- Damage only ever lowers hp through `applyDamage`; healing only raises it
  through `applyHealing`/`gainHp`. Never write `currentHp` directly.
- Never write `position` without an `isPositionBlocked` + bounds check.
  For chosen movement use `moveToward`.

## Determinism

```ts
import { SeededRng, withRng } from 'battlecast-engine';

withRng(new SeededRng('my-seed'), () => {
  // every engine call in here uses the seeded stream
});
```

The `Encounter` does this for you when constructed with a seed. Engine
calls are synchronous, so scoping is exact even with many encounters
interleaved in one process.

## Content

```ts
import { monsters, getMonsterByName, searchMonsters, buildHero } from 'battlecast-engine';

getMonsterByName('Adult Red Dragon')   // full statblock or undefined
searchMonsters('undead')               // name/type/CR substring match
buildHero('Wizard', 9)                 // MonsterData for a level-9 Wizard
```

See `docs/rules-coverage.md` for exactly which 5e mechanics the engine
implements.
